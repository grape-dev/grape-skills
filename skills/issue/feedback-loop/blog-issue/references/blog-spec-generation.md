# 博客 Spec 生成指南（内容规格）

> 配套 `skills/issue/feedback-loop/blog-issue/SKILL.md`（B 链路）与 runbook Step B2。所有平台操作用 grape CLI，禁止 curl 直连平台 API；curl 仅限外部博客系统（BLOG_HOST）验证。

## 执行前提

- 已判定为博客场景（见 `blog-scene-detection.md`）
- 四维可产出性分析已完成，评级 `ready`
- VOD A2A context 中的「博客需求清单」已解析（如有——含 topic/focus/structure/images/video/labels/length/tone）

## 输入来源

| 输入 | 来源 | 用途 |
|------|------|------|
| 博客需求清单 | VOD A2A context 的 `requirement_summary` | 主题/风格/结构/配图/视频/长度/语调/标签 |
| Issue 正文 / 评论 | `grape issues detail` + `grape git-repo issues comments list` | 原始需求描述、参考链接、用户补充 |
| 博客系统地址 | 知识基线 `project-info/member/blog-config.yaml` 的 blog.host 或 Issue 上下文（runbook B1 解析顺序）| 发布目标 `$BLOG_HOST` |
| AI 模型配置 | 知识基线 `project-info/member/ai-models.yaml` | 配图（qwen-image）/视频（Wan2.2）的 url/key/model |
| 博客系统可用接口 | 外部 curl 探测 `$BLOG_HOST`（/api/lables、/api/articles——仅外部服务）| 确认发布接口 |

## 博客 Spec 模板

```markdown
# Spec: Issue #{number} — {博客标题}

> Generated by Blog Issue Agent | Producibility: ready | {datetime}

## Objective
- **要生成什么**：一篇图文并茂的博客文章（含 AI 生成配图 + AI 生成视频）
- **主题**：{从需求清单提取}
- **风格**：{科技评测/轻松科普/营销推广/...}
- **目标读者**：{技术开发者/产品经理/普通用户/...}
- **成功标准**：博客成功发布到 {BLOG_HOST}，首页可见，含可播放视频和可显示配图

## 博客内容规格

### 文章结构
- 章节数：{N} 章节
- 章节标题：{从需求清单提取}
- 字数：{标准 ~1200字 / 深度 ~2000字}
- 特殊元素：{参数对比表格/引用块/高亮块/...}

### 配图规格
- 数量：{N} 张
- 风格：{写实产品风/科技概念风/...}
- 生成方式：AI 配图（qwen-image——按 ai-models.yaml image 段配置）
- 封面图描述：{封面图画面要求}

### 视频规格
- 时长：{5} 秒
- 生成方式：AI 视频（T2V 文生视频——按 ai-models.yaml video 段配置；I2V 有后端 bug 禁用）
- 画面描述：{视频画面构想}
- 旁白语调：{专业介绍/情感氛围/...}

### 发布目标
- 博客系统地址：{BLOG_HOST}
- 发布接口：POST /api/articles + POST /api/upload
- 标签 ID：{从 /api/lables 查询匹配}

## Technical Approach

### 生成流程（coding 博客内容生成技能执行）
1. 撰写 HTML 文章正文（含 {N} 章节 + 特殊元素）
2. 调用 AI 配图（ai-models.yaml image 段）生成 {N} 张配图（含封面）
3. 调用 AI 视频（ai-models.yaml video 段——T2V）生成 5 秒视频
4. 组织产物到 blog/{topic-slug}/ 目录
5. 提交 PR 到仓库 dev 分支

### 发布流程（sre 博客发布技能执行）
1. 合并 PR
2. 从 blog/{topic-slug}/ 读取 index.html + 媒体文件
3. 上传媒体到博客服务器（POST /api/upload）
4. 替换 HTML 中的相对路径为上传 URL
5. 发布文章（POST /api/articles）

## Acceptance Criteria（内容验收——非功能验收）
- [ ] 文章含 {N} 章节，字数符合规格
- [ ] 配图 {N} 张，封面图存在
- [ ] 5 秒视频可播放
- [ ] PR 已创建，blog/{topic-slug}/ 目录结构完整
- [ ] SRE 发布后博客首页可见
- [ ] 文章详情页 https://{BLOG_HOST}/article/{id} 渲染正确（含配图与视频）

## Risks & Mitigations
| Risk | Impact | Mitigation |
|------|--------|------------|
| AI 模型 API 不可用 | High | 发布前验证 ai-models.yaml 配置有效性（外部 AI 服务 url 可达）+ BLOG_HOST 可达性 |
| 图片/视频生成超时 | Med | 每张图 60s 超时，视频 120s 超时，失败重试 1 次 |
| 博客系统不可达 | Med | Spec 生成前外部 curl /health 验证；不可达 → Spec 标注「发布目标待验证」（不阻塞内容生成交办）|
| 产品外观与实物不符 | Med | 涉及具体产品时须先官网调研提取视觉特征 |
```

## 发布方式（全部 grape CLI）

### 作为 Issue 评论发布

```bash
# 长 body 先写文件再 @file（外层单引号防 shell 转义）：
printf '%s' '{"body":"[blog-issue Agent] 📋 博客 Spec Document\n\n{Spec 正文}"}' > /tmp/blog-spec.json
grape git-repo issues comments create --owner "$REPO_OWNER" --repo "$REPO_NAME" --number "$ISSUE_NUMBER" \
  --json @/tmp/blog-spec.json --json-out
```

格式要求：
- 评论 body 前缀：博客链路 `[blog-issue Agent]` + Spec 标记 `📋 博客 Spec Document`
- Spec 内容使用完整 markdown 格式

### 打标签

```bash
# 幂等——先 list 查重，缺失才 create：
grape git-repo labels list --owner "$REPO_OWNER" --repo "$REPO_NAME" --json-out
grape git-repo labels create --owner "$REPO_OWNER" --repo "$REPO_NAME" --json '{"name":"spec-ready","color":"#0e8a16"}'
grape git-repo labels create --owner "$REPO_OWNER" --repo "$REPO_NAME" --json '{"name":"blog-issue","color":"#f9d0c4"}'
# 打标（整体替换语义——携带既有标签）：
grape git-repo issues update --owner "$REPO_OWNER" --repo "$REPO_NAME" --number "$ISSUE_NUMBER" \
  --json '{"labels":"{既有标签,}spec-ready,blog-issue"}' --json-out
```

### 分配给机器人

```bash
grape git-repo issues update --owner "$REPO_OWNER" --repo "$REPO_NAME" --number "$ISSUE_NUMBER" \
  --json '{"assignee":"{GitCode 用户名}"}' --json-out
```

## A2A 交办 coding（博客专属）

博客 Spec 发布 + 打标 + 分配完成后，A2A 交办 coding（**命令与 context 详见 runbook B4**——context 构造规则：①评级 ready ②明确指定「博客内容生成技能」（内容产出非通用开发）③携带博客规格摘要/发布目标 ④告知 Spec 在 Issue 评论 ⑤提示完成后 A2A sre 发布、**跳过 QA**）。

## Spec 版本管理

与通用链路一致：用户提出修改 → 更新章节 → 版本号 +1 → 重新发布 → A2A 重新通知 coding（先查 pipeline 防重复）。
