# 博客场景识别与分流

> 配套 `skills/issue/feedback-loop/blog-issue/SKILL.md` 与 runbook Step 1。

## 判定流程（按序判定，命中即分流）

博客场景识别后，blog-issue 对**所有**进入 issue 阶段的 Issue 都处理：博客走 B 链路（内容产出），非博客走 G 链路（通用软件交付）——不存在「不做处理」。

### 第一步：优先级判定（最高级信号）

| 信号 | 判定 |
|------|------|
| VOD A2A context 携带「博客需求清单」（`requirement_summary` 结构——含 topic/focus/structure/images/video/labels/length/tone）| **博客场景**（直接走 B 链路）|
| Issue 已带博客需求澄清标签（如 `blog-vod` / `blog-issue`）| **博客场景** |

### 第二步：关键词匹配（无上述信号时）

| 特征关键词 | 判定 |
|-----------|------|
| 含「博客」「文章」「图文并茂」「写文章」「发博客」「专栏」「博文」| 博客场景候选 |
| 含「配图」「AI 生成视频」「配视频」「封面图」+ 产品/概念名称 | 博客场景候选 |
| 含「代码实现」「bug」「编译」「部署」「PR 审查」等非博客关键词 | 非博客场景 |
| 以上都不匹配 | 非博客场景 |

### 第三步：内容确认（关键词命中候选后）

关键词命中后，进一步确认 Issue 正文/评论是否包含以下任一特征：
- 要求生成/撰写/发布**文章内容**（非代码）
- 要求 AI 配图、AI 视频、图文穿插
- 要求发布到**博客网站/知识库/博客系统**
- VOD A2A context 中携带「博客需求清单」

命中 → 博客场景（B 链路）；未命中 → 通用场景（G 链路）。

## 判定后的动作

- 场景识别结论用评论说明一次（博客链路前缀 `[blog-issue Agent]`；通用链路前缀 `[issue agent]`），说明依据（哪条信号命中）
- 判定存疑（关键词双向命中：既含博客词又含代码词）→ 以**内容确认**为准（要求生成文章/发布博客 = 博客；要求改代码/修 bug = 通用）

## 博客链路 vs 通用链路

| 维度 | 通用链路（G）| 博客链路（B）|
|------|-------------|-------------|
| Spec 格式 | 通用 Spec（spec-generation.md）| 博客 Spec（blog-spec-generation.md——主题/风格/结构/配图/视频/长度/语调/标签/发布目标）|
| A2A 目标 | coding（通用开发）| coding（**指定博客内容生成技能**生成内容）|
| 后续链路 | coding → qa → sre（完整交付）| coding → sre（**跳过 QA**——内容产物无需代码审查）|
| SRE 职责 | 通用部署 | 合并 PR + 调用博客 API 发布文章 |
| 验收标准 | 功能/测试/部署 | 内容可见、视频可播放、配图可显示 |

## 链路总览

```
VOD（需求澄清，已完成）
  → A2A → blog-issue（本技能：分析 → 博客 Spec → A2A）
    → A2A → coding（博客内容生成技能：生成正文+配图+视频 → 提交 PR）
      → A2A → sre（博客发布技能：合并 PR → 上传媒体 → 发布文章）
```

⚠️ 博客链路中 QA 阶段跳过：博客产物是 HTML/图片/视频内容文件，不涉及代码逻辑变更，无需代码审查。coding 提交的 PR 中只有 `blog/` 目录下的内容文件，SRE 合并后直接发布。
