# 风险评级矩阵

## 目标

综合变更面、影响面、测试覆盖、签名变更，给出风险等级与合并建议。

## 五维评估

| 维度 | 权重 | 取值 | 评分 |
|------|------|------|------|
| 变更面大小 | 中 | 符号数 | 1-2 低 / 3-8 中 / 9-20 高 / >20 关键 |
| 影响面深度 | 高 | 最大跳数 | 0 低 / 1 中 / 2 高 / ≥3 关键 |
| 入口点触及 | 高 | 触及入口点数 | 0 低 / 1 中 / 2 高 / ≥3 关键 |
| 测试覆盖率 | 高 | 覆盖率 | ≥80% 低 / 50-79% 中 / 20-49% 高 / <20% 关键 |
| 签名变更 | 高 | 签名变更符号数 | 0 低 / 1 中 / 2-3 高 / ≥4 关键 |

## 综合评级算法

按权重加权，关键维度（高权重）一票否决：

1. 任一高权重维度 = 关键 → 综合关键
2. 任一高权重维度 = 高 → 综合至少高
3. 多数维度 = 中 → 综合 中
4. 全部维度 = 低 → 综合 低

特殊规则：
- **无测试覆盖 + 触及入口点** → 至少高（入口变更无兜底）
- **签名变更 + 影响面深度 ≥2** → 至少高（破坏性变更传播）
- **全部 unobserved** → 至少中（证据不足，不确定性高）

## 风险等级定义

| 等级 | 图标 | 含义 | 合并建议 |
|------|------|------|---------|
| 低 | 🟢 | 变更小、影响面浅、有测试覆盖 | 可合并 |
| 中 | 🟡 | 有一定影响但可控 | 建议跑通测试后合并 |
| 高 | 🟠 | 影响面大或无测试覆盖 | 建议补测试/人工确认后合并 |
| 关键 | 🔴 | 破坏性变更触及入口点且无兜底 | 强烈建议人工审查 + 补测试后再合并 |

## 合并建议生成

按风险等级 + 具体短板生成建议文字（不硬阻断）：

### 低风险
```
变更面小，影响面可控，测试覆盖完整。可合并。
```

### 中风险
```
建议合并前：跑通现有测试套件确认无回归。
{若有 unobserved：建议生成 codegraph 索引后复评影响面。}
```

### 高风险
```
建议合并前：
{若无测试覆盖：补齐 {uncovered_symbols} 的测试用例。}
{若触及入口点：确认入口点 {entrypoints} 的调用方兼容。}
{若有签名变更：确认签名变更 {changed_signatures} 的向后兼容性。}
{若有 unobserved：建议生成 codegraph 索引后复评影响面。}
```

### 关键风险
```
强烈建议合并前人工审查：
{若无测试覆盖：必须补齐 {uncovered_symbols} 的测试用例。}
{若触及入口点：必须确认入口点 {entrypoints} 的所有调用方兼容（含跨语言）。}
{若有签名变更：必须评估签名变更 {changed_signatures} 的破坏性影响。}
本评估未阻断合并，最终决策由维护者定。
```

## 评级边界

- **纯文档变更**：不评级（跳过影响分析）
- **单函数 trivial 变更**：仅评变更面 + 测试覆盖，不评影响面（简化模式）
- **全部 unobserved**：评级封顶中（证据不足不给高/关键，但标注 `low_confidence`）
- **跨语言断点多**：评级 +1 档（不确定性高）
