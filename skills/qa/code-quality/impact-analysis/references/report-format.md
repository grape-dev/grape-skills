# 输出报告契约

## 目标

定义 PR 审查报告的 Markdown 格式，作为 PR 评论 body 发送。报告合并 qa 全生命周期审查（配置检查 + 代码审查 + Skill 审查 + IaC 审查 + 工作流审查 + 安全扫描 + 合并检查）与影响范围评估（变更面 + 影响面 + 测试覆盖 + 风险评级）。

## 报告结构

```markdown
## [$AGENT_NAME] 审查报告

### 关联 Issue
- Closes #N — 状态: triaged

### 变更摘要
- 文件: X 个文件变更，+Y -Z
- 评估模式：完整模式 / 简化模式 / 跳过（纯文档）

### 配置检查
- ✅ Title：通过
- ✅ Description：通过
- ⚠️ Labels：缺少分类标签
- ⚠️ Assignee：未设置

### 代码审查
**结论**: ✅ 通过 / ⚠️ 需修改 / ❌ 需重大修改

| 级别 | 文件 | 行号 | 问题 | 建议 |
|------|------|------|------|------|
| 🔴 | src/main.go | 42 | 硬编码密钥 | 使用环境变量 |
| 🟡 | src/api.py | 88 | 缺少错误处理 | 添加 try/except |

### Skill 审查（仅当 PR 修改 skills/ 目录）
**结论**: ✅ 通过 / ⚠️ 需修改

| 级别 | 文件 | 问题 | 建议 |
|------|------|------|------|

### IaC 审查（仅当 PR 包含 IaC 文件）
**结论**: ✅ 安全 / ⚠️ 需修改

| 级别 | 文件 | 行号 | 问题 | 建议 |
|------|------|------|------|------|

### 工作流审查（Agent Work Loop）
**结论**: ✅ 健康 / ⚠️ 需改进 / ❌ 差距明显

| 维度 | 证据状态 | 严重度 | 发现 | 影响 | 修复 | 验收 |
|------|---------|--------|------|------|------|------|
| 变更验证 | ✅ 已观察 | 🔴 Critical | PR 无测试且 CI 未运行 | 回归风险 | A2A 补测试并跑 CI | 测试通过且 CI 绿 |
| 经验沉淀 | ⚠️ 未观察 | 🟡 Required | 未发现可复用 skill | 问题易复发 | 沉淀修复为 skill | 新 skill 存在 |

### 影响范围评估
**风险评级**: 🟢 低 / 🟡 中 / 🟠 高 / 🔴 关键

#### 变更面
| 文件 | 符号 | 类型 | 行号 | 签名变更 | 签名变更详情 |
|------|------|------|------|---------|-------------|
| src/api/event_pipeline.py | run_pipeline | function | 239-507 | 是 | 参数新增 strict_mode |
| src/runtime/service.py | claim | function | 369-487 | 否 | — |

#### 影响面
| 受影响符号 | 文件 | 经由 | 跳数 | 证据 | 入口点 | 观察状态 |
|-----------|------|------|------|------|--------|---------|
| webhook.handle | src/api/routes/webhook.py | run_pipeline | 1 | codegraph 边: webhook.py:11 | 是 | ✅ observed |
| scheduler.dispatch | src/runtime/service.py | webhook.handle | 2 | LLM 推断 + service.py:45 | 否 | ⚠️ unobserved |

#### 测试覆盖
| 测试文件 | 测试符号 | 覆盖目标 | 证据来源 | 质量 |
|---------|---------|---------|---------|------|
| tests/test_event_pipeline.py | test_run_pipeline | run_pipeline | naming + reference + codegraph_edge | 高 |

**覆盖率**: 3/5 符号有测试（60%）
**无测试覆盖**: scheduler.dispatch, worker.claim

#### 风险评级矩阵

| 维度 | 取值 | 评分 |
|------|------|------|
| 变更面大小 | 5 符号 | 中 |
| 影响面深度 | 2 跳 | 高 |
| 入口点触及 | 2 个 | 高 |
| 测试覆盖率 | 60% | 中 |
| 签名变更 | 1 个 | 中 |

触发特殊规则：无测试覆盖 + 触及入口点 → 至少高

#### 合并建议
建议合并前：
- 补齐 scheduler.dispatch, worker.claim 的测试用例
- 确认入口点 webhook.handle, api.chat.send 的调用方兼容
- ⚠️ 2 条调用链为 LLM 推断（unobserved），建议生成 codegraph 索引后复评影响面

本评估未阻断合并，最终决策由维护者定。

### 安全扫描
**结论**: ✅ 安全 / ⚠️ 发现问题

### 合并检查
- ✅ 安全通过
- ✅ 审查通过
- ⚠️ 测试未确认
```

## 字段说明

### 配置检查
- PR 基本配置项（Title / Description / Labels / Assignee / Issue 关联）的通过/不通过状态

### 代码审查表
- **级别**：🔴 Critical（阻断）/ 🟡 Required（必须修复）/ 💬 Optional（建议）/ Nit（可选）
- **文件**：问题所在文件路径
- **行号**：问题所在行号
- **问题**：问题描述
- **建议**：修复建议

### 工作流审查表
- 按 `findings-format.md` 契约输出（维度、证据状态、严重度、发现、影响、修复、验收）

### 变更面表
- **文件**：变更文件路径
- **符号**：函数/类/方法名
- **类型**：function / class / method / component / field
- **行号**：符号定义行号范围
- **签名变更**：是/否
- **签名变更详情**：签名变更的具体内容（参数增删/类型/可见性等）

### 影响面表
- **受影响符号**：调用变更符号的函数
- **文件**：受影响符号所在文件
- **经由**：通过哪个符号传播过来（1 跳时为变更符号本身）
- **跳数**：1 = 直接调用，2 = 间接调用
- **证据**：codegraph 边 / LLM 推断 + 文件位置
- **入口点**：是/否（公共 API/路由/handler/CLI main）
- **观察状态**：✅ observed（codegraph 证实）/ ⚠️ unobserved（LLM 推断）

### 测试覆盖表
- **测试文件**：测试文件路径
- **测试符号**：测试函数/方法名
- **覆盖目标**：被测的变更符号
- **证据来源**：naming / reference / codegraph_edge（可组合）
- **质量**：高/中/低（见 test-matching.md 匹配质量评级）

### 风险评级
- **结论**：🟢 低 / 🟡 中 / 🟠 高 / 🔴 关键
- 五维评分表
- 触发的特殊规则（如有）

### 合并建议
- 按风险等级生成（见 risk-rating.md）
- 列出具体短板和补救动作
- 始终以"本评估未阻断合并，最终决策由维护者定"结尾（不硬阻断）

## 简化模式报告

单函数 trivial 变更时，省略影响面表，仅输出变更面 + 测试覆盖 + 风险评级：

```markdown
### 影响范围评估
**风险评级**: 🟢 低

#### 变更面
| 文件 | 符号 | 类型 | 行号 | 签名变更 |
|------|------|------|------|---------|
| src/util.py | format_time | function | 45-52 | 否 |

#### 测试覆盖
| 测试文件 | 测试符号 | 覆盖目标 | 证据来源 | 质量 |
|---------|---------|---------|---------|------|
| tests/test_util.py | test_format_time | format_time | naming + reference | 高 |

**覆盖率**: 1/1（100%）

#### 合并建议
变更小，有测试覆盖。可合并。
```

## 跳过模式报告

纯文档/配置变更时，省略整个影响范围评估章节：

```markdown
### 影响范围评估
无代码符号变更，跳过影响范围评估。
```

## 全部通过时的简报

```markdown
[$AGENT_NAME] 审查通过，所有检查项均正常。
```

## 格式约束

- body **必须**以 `[$AGENT_NAME]` 开头
- 表格列顺序固定（见上述各表）
- observed/unobserved 用 ✅/⚠️ 图标
- 风险等级用 🟢/🟡/🟠/🔴 图标
- 严重度用 🔴 Critical / 🟡 Required / 💬 Optional / Nit
- 无数据的表格章节标注"无"或省略该章节
- 不输出 token/密码/敏感信息
