# Grilling 澄清指南（VOD-MattPocock）

> 内化 mattpocock `grill-me` / `grilling` 的「逼问收敛至无歧义」纪律，落地为 grape 评论 + awaiting-input 交互。
> 核心区别：mattpocock 倾向无条件逼问；本技能结合 grape「先调查」——**先基于项目调查，再以 Grilling 纪律收敛残留歧义**。

## 一、Grilling 纪律（每轮必须遵守）

1. **三段式输出**（评论正文）：
   ```
   [VOD Agent]
   - 已确认：{已从 Issue/问答确认的点}
   - 仍未确认：{影响实现的点}
   - 请补充：{1-3 个具体问题，结合项目现状，不用"请提供更多信息"}
   ```
2. **问题必须可执行**：不是"你是什么意思"，而是给出候选 + 追问（如"是 A 还是 B？或两者都要？"）；问题基于调查结果。
3. **不重复已确认项**：每轮只问未确认 + 新出现的问题；已确认的写入"已确认"段，不再次问。
4. **≤3 轮**：超限 → 评论列「已确认/缺失项」标「待澄清」，不再无限追问。

## 二、判定：是否达到"无歧义可交棒"

收敛结论中若出现以下任一 → **继续澄清，不交棒**：
- 「可能指 A 或 B」「A/B 两条路径」「暂定/先按…」
- 验收标准不唯一可测（一个验收对应多种行为）
- 目标/用户故事可同时解释为两个不同功能

达到无歧义：目标唯一、行为路径唯一、验收可测、Out of Scope 明确。

## 三、需求单模板（收敛后评论发布）

```markdown
## 目标
{一句话，唯一可执行}

## 用户故事
1. As a <角色>, I want <能力>, so that <价值>
2. ...                 # 覆盖所有场景的完整列表

## 验收标准
- [ ] {可测、唯一解释的验收项}
- [ ] ...

## Out of Scope
- {明确不做/边界}

---
来源：Issue #{n} | Grilling 收敛
auto-submitted by VOD-MattPocock Agent
```

## 四、领域词汇（GLOSSARY 意识）

- 仓库有 `GLOSSARY.md` → 提问与收敛一律用其词汇；发现新领域词 → 在需求单中提议补充 GLOSSARY（不自行写文件，交由 issue/coding）。
- 无 GLOSSARY → 收敛中对易混术语给出一致表述，避免下游代语歧义。

## 五、话术示例

```
用户："希望支持批量操作"
VOD（结合项目调查）：
[VOD Agent]
- 已确认：目标是对 {对象X} 做批量操作
- 仍未确认：批量操作的范围与形态
- 请补充：1) 批量作用于 {X} 的哪些行为（删除/更新/导出）？
        2) 是仅后端接口，还是需要前端入口？3) 批量数量上限有要求吗？
```
