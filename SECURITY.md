# Security Policy

Security vulnerabilities should **never be reported via public Issues** — that exposes everyone to risk before a fix exists.

## Reporting a Vulnerability

- Send a **private message** to the maintainers on GitCode, or use the repository's private contact channel listed in the GitCode settings.
- Include:
  - Affected component / repository / skill and version
  - Trigger conditions and reproduction steps
  - Expected vs actual behavior
  - Suggested fix (optional)
- **Do not** publish exploit details or PoC publicly.

We will evaluate the report confidentially, fix it, and acknowledge the reporter in release notes when appropriate.

## For Contributors

- Never commit tokens, API keys, passwords, or other secrets (see [CONTRIBUTING](CONTRIBUTING.md)).
- Use placeholders for any credentials in skill content and templates.
- If you discover an existing secret, report it privately and rotate the credential immediately.
